# T-121 · 「重练此题」迷你练习

| 轨道 | 里程碑 | 预估 | 依赖 | 阻塞 |

| Full-stack | M3 | 1.5d | T-040, T-101, T-105, T-108 | — |

## 背景
报告页的主问题和每条历史追问都需要独立重练入口（PRD §3.8）。本任务实现聚焦于同一主问题链的迷你练习模式。

## 目标
从报告进入单题练习：重练主问题时允许面试官正常追问后结束；重练历史追问时只回答该追问一次；两种模式都给出与原回答的对比反馈。

## 范围
- **做**：后端创建「单题练习」轻量会话（限定在一个主问题链内）、前端报告页内的专注答题弹窗（复用正式面试的实时通信与文字/语音能力，但采用独立界面）、主问题与每条追问的重练入口、练习结果与原答案对比。
- **不做**：完整多题面试（已有）；练习历史沉淀可最小化。

## 技术规格
- 主问题重练运行正式面试的追问决策，最多追问 3 次；决策准备进入下一道主问题时直接结束练习并批改，不生成下一道主问题。
- 历史追问重练只接受一次回答：展示选中的追问 → 用户提交回答 → 自动结束并批改，不再产生追问。
- 复用正式面试已有的文字流、录音、ASR、TTS、消息持久化与断线恢复能力，不复制实时通信逻辑；会话类型标记为「单题练习」。
- 即时评分复用 T-105 的**单题批改 chain**（`QuestionReview` 结构化输出），不重写评分逻辑。
- 当批改输入携带来源回答时，`QuestionReview` 同时返回结构化评分差异：`improvements`（本次提升点）、`remainingGaps`（仍然不足）与 `scoreRationale`（新旧分数为何不同）。已有来源分数必须作为基线原样解释；旧追问没有历史分数时，才由同一批改 chain 补评基线分。
- 后端：`POST /interviews/{sessionId}/questions/{questionId}/retry` → 建练习子会话，返回 practice sessionId；结束后给该题的即时评分与对比。
- 前端：主问题显示「重练主问题」，每条追问显示「重练此追问」，都打开专用弹窗。作答阶段只显示当前提示、本次回答和语音/文字控件，不嵌入或缩放正式面试页面；共享其 SSE/WebSocket、消息恢复、录音、ASR 与 TTS 运行能力。结束后原地展示「本次 vs 上次」对比及本次追问链。

## 涉及文件
- 后端 `interview/PracticeController.java` + service（复用面试基础设施）
- AI 侧：为 `interview_agent` 增加单次作答的 practice 模式，并复用 `grading` 的单题 chain；禁止复制粘贴实时通信或评分逻辑
- 前端：报告卡按钮接入 + `PracticeDialog` + 独立 `PracticeAnswerCard`，通过无头运行层复用正式面试的实时与语音组件

## 验收标准
1. 从报告某题打开独立设计的专注答题弹窗；弹窗不出现正式面试页头、总计时、题目进度、面试官舞台、回看或结束面试控件。
2. 作答阶段隐藏原答案、原得分和改进建议；主问题可正常产生最多 3 条追问，但不进入下一道主问题；历史追问只回答一次。
3. 展示本次与上次回答/得分对比，并展示“为什么是这个评分”：明确本次提升点、仍然不足和分差结论；每条追问拥有独立的 0–10 分评分，旧报告缺少追问分数时在本次批改中按同一标准补评基线分。
4. 练习不污染原面试记录与统计（或明确单独计）。
5. `lint`/`typecheck`/`test`/`build` 通过。

## 验证方式
PR 贴：从报告打开练习弹窗 → 文字/语音作答一次 → 自动批改 → 对比的全流程截图。
