# 统一面试回答框设计

日期：2026-08-11
状态：待 owner 书面审核
范围：正式面试页底部回答区；不改变问题展示、报告页或服务端 ASR 协议

## 1. 目标

将当前分离的“语音回答 / 打字回答”模式合并为一个统一回答框。用户始终编辑同一份答案，可以随时键盘输入，也可以通过麦克风把实时转写写入该答案。界面只保留一个录音操作入口，并继续跟随系统明暗主题。

成功标准：

- 页面不再展示语音/打字模式切换按钮。
- 文本输入框始终存在，语音转写和键盘输入共享同一内容。
- 麦克风按钮是唯一的录音开始/停止入口。
- 录音状态条只提供状态与音量反馈，不可点击。
- 切换连接或语音失败时不丢失已经输入的答案。
- 桌面端和移动端均能清楚完成“输入或录音 → 编辑 → 提交”。

## 2. 视觉结构

回答区由一张悬浮卡片组成，宽度沿用当前正式面试页的内容尺度。

1. **编辑区**：占据卡片主体，最小高度约 96px，最多增长到 160px 后内部滚动。占位文案为“输入回答，或点击下方麦克风开始语音输入……”。
2. **录音状态条**：仅在录音期间出现在编辑区上方，展示“正在聆听”、真实音量声波和“实时转写中”。整条状态不可点击，也不出现第二个停止按钮。
3. **底部工具栏**：左侧为麦克风主操作，中间为简短提示，右侧为字数与提交按钮。
4. **麦克风状态**：空闲时显示“语音输入”；连接语音服务时显示“正在连接语音…”并禁用重复点击；录音时显示“停止并转写”。
5. **提交按钮**：使用深色高对比按钮；有有效答案且会话可提交时启用。录音期间禁用，防止音频尾帧尚未完成时提前提交。

浅色主题使用暖白卡片、细灰边框和橙色语音强调；深色主题使用现有深灰卡片和同一橙色强调。两种主题共享布局、状态语义和焦点样式。

## 3. 交互规则

### 3.1 键盘输入

- 文本框在加载完成且当前问题可回答时始终可编辑，不依赖语音连接状态。
- `Enter` 提交，`Shift + Enter` 换行；录音期间不响应快捷提交。
- 用户手工编辑后的内容是唯一答案草稿，后续转写不得用旧结果覆盖较新的手工编辑。

### 3.2 开始录音

- 若语音 WebSocket 已就绪，点击“语音输入”后立即请求麦克风并开始采集。
- 若当前仍使用文字 SSE，点击后先切换到语音 WebSocket；按钮显示“正在连接语音…”。连接成功后自动开始录音，无需用户再次点击。
- 切换传输通道期间保留当前文本、问题标识和事件游标，避免重复问题或丢失草稿。

### 3.3 录音与转写

- 录音开始后，底部按钮切换为“停止并转写”，上方出现不可交互的状态条。
- `asr_partial` 更新统一编辑区；最终转写到达后内容仍可修改。
- 若用户在部分转写上进行了编辑，客户端需要避免相同旧片段反复覆盖编辑结果；沿用现有转写去重逻辑并补充回归测试。

### 3.4 停止与提交

- 点击“停止并转写”先冲刷本地尾帧，再发送 `audio_end`。
- 状态条切换为“正在完成转写…”，最终结果到达后消失。
- 提交使用当前编辑区内容。语音 WebSocket 已启用时沿用 `asr_confirm`；纯文字链路沿用现有 HTTP 提交流程。

## 4. 连接与异常处理

- 语音服务未配置、鉴权失败或连接失败：保留当前答案，退出录音态，继续允许文字输入，并展示可关闭的错误提示。
- 麦克风权限被拒绝：保持统一回答框，不隐藏文本输入；提示用户在浏览器地址栏授权后重试。
- 录音过程中连接中断：本地停止采集并冲刷可用尾帧，保留已转写内容，麦克风按钮进入重连/重试状态。
- 会话结束、正在提交或面试官正在生成下一题时：编辑区和麦克风遵循现有回答锁定规则。

## 5. 组件边界

- `InterviewClient`：管理统一答案草稿、文本/语音传输通道切换、连接状态和提交路径。
- `VoiceRecorder`：管理麦克风权限、AudioContext、PCM16/16k 采集、尾帧冲刷、真实音量和唯一录音按钮。
- `Waveform`：只负责展示真实音量，不承担点击行为。
- `TTSPlayer`：保持现有面试官语音播放职责，不进入回答框主交互。

不新增第二套答案状态，不复制 WebSocket 客户端，也不改变 `/ws/interview/{session_id}` 的 `type/payload/seq` 协议。

## 6. 响应式与无障碍

- 桌面端工具栏单行排列；窄屏下提示文案可隐藏，麦克风与提交按钮仍保持至少 44px 点击高度。
- 录音按钮使用明确的 `aria-label` 和 `aria-pressed`；状态条使用 `role="status"` 与 `aria-live="polite"`。
- 禁用、连接中、录音中不能只靠颜色区分，必须同时有文字和图标变化。
- 遵循 `prefers-reduced-motion`：声波仍反映音量，但不增加装饰性位移或脉冲动画。
- 聚焦文本框、麦克风和提交按钮时提供清晰焦点环。

## 7. 验证范围

自动化测试至少覆盖：

- 不再渲染语音/打字模式切换按钮。
- 文字输入无需语音连接即可编辑和提交。
- 首次点击麦克风会完成文字链路到语音链路的切换，并在连接后自动开始录音。
- 录音时仅有一个“停止并转写”按钮，状态条不可点击。
- 停止时先冲刷尾帧再发送 `audio_end`。
- 部分/最终 ASR 更新同一编辑区，手工编辑不会被重复事件冲掉。
- Deepgram/权限/网络失败后保留草稿并继续允许文字回答。
- 浅色、深色、移动端和 reduced-motion 样式回归。
