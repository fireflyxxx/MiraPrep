# T-121 单题重练弹窗重设计

## 背景与目标

T-121 已建立独立 `PRACTICE` 子会话、一次作答后自动结束、单题批改与结果对比能力。原前端方案通过给正式面试组件增加 `practice-dialog` 呈现模式，将缩小版正式面试页面嵌入弹窗。该方案保留了正式面试的页头、计时、进度和面试官舞台，不能形成清晰的“只重新回答这一题”的产品心智。

本次重设计将弹窗改为独立的“专注答题卡”。正式面试与单题重练共享实时会话、消息恢复、文字提交、WebSocket 语音、ASR、TTS 和断线恢复能力，但使用完全不同的视觉组件。

## 已确认的产品取舍

- 用户从三种候选方向中选择 A“专注答题卡”。
- 作答阶段隐藏原答案、原得分与改进建议，避免旧答案造成锚定。
- 每次重练只接受一次回答；提交后自动结束，不追问、不生成下一题。
- 结果仍在当前弹窗内展示，不跳转正式面试页面或独立结果页。

## 作答界面

弹窗沿用报告页的明亮视觉语言。桌面端宽度约 720px，移动端接近视口全宽并使用安全区内边距。

信息层级从上至下为：

1. “重新回答这道题”标题与关闭按钮。
2. 浅橙色题目卡，包含题目编号、完整题干和播放/重播题目的轻量入口。
3. “语音回答 / 文字回答”分段控件。
4. 当前回答工作区。
5. “只提交一次 · 不会追问”提示和唯一主操作“提交本次回答”。

不展示正式面试 Logo、会话编号、总计时、题目进度、Mira 面试官头像、回看入口和“结束面试”按钮。

## 文字与语音交互

文字模式提供多行输入框。空答案、正在提交、连接不可用或会话已结束时禁用提交。

语音模式复用正式面试的录音、PCM16/16k 音频帧、WebSocket、ASR 与 TTS 能力：

- 展示麦克风控制、录音状态、录音时长和实时转写状态。
- ASR 结果写入与文字模式相同的可编辑回答框，用户可在提交前修正。
- 切换语音/文字模式不清空当前答案。
- 题目区提供播放/重播入口，不显示面试官头像或舞台。
- 浏览器不支持语音或 provider/鉴权不可用时，明确说明原因并降级到文字模式。

## 状态流转

- `creating`：创建独立练习会话，显示轻量准备状态。
- `active`：显示专注答题卡，只允许提交一次。
- `grading`：提交后锁定输入，原地显示批改进度。
- `ready`：展示题目、分差、上次回答与本次回答，以及本次建议；提供“返回报告”和“再练一次”。
- `failed`：显示可理解的失败原因，并允许重新发起练习。

弹窗始终提供可发现的关闭入口。已有草稿、正在录音或会话仍处于 active 时，关闭前二次确认；确认关闭后停止麦克风轨道、WebSocket、SSE 和 TTS。评分与结果状态可以直接关闭。

## 前端架构

不再通过 `InterviewClient` 的 `presentation` 参数复用整张正式面试页面。

将 `InterviewClient` 中与视觉无关的运行时能力提取为共享层（hook 或等价的无头控制器），负责：

- 恢复运行时 token、持久化消息及事件/音频游标。
- SSE 与语音 WebSocket 连接、重连和降级。
- interviewer 事件、ASR、TTS 音频与结束事件处理。
- 文字/语音答案提交、幂等 answerId 和待提交恢复。
- 卸载时的请求、连接、录音与音频清理。

正式面试页面继续由 `InterviewClient` 呈现；新增专用的单题练习答题组件供 `PracticeDialog` 使用。`VoiceRecorder`、`TTSPlayer`、`Waveform` 和底层 API transport 继续复用。

正式面试的视觉和现有用户行为不因本次重构改变。

## 错误与边界

- 无效 sessionId、运行时 token 缺失、历史恢复失败和连接耗尽均在弹窗内展示。
- 语音连接返回未配置、鉴权失败或建立失败时停止录音状态并切回文字回答。
- 重复实时事件按 seq 去重；重复提交复用相同 answerId。
- `interview_end` 只触发一次从 active 到 grading 的转换，避免 React effect 或流事件重复启动结果查询。
- 来源会话、消息、报告和统计保持只读，练习数据继续由独立 `PRACTICE` 子会话持久化。

## 测试与验收

前端组件测试覆盖：

- 弹窗不再渲染正式面试 shell、页头、计时和面试官舞台。
- 题目、模式切换、草稿保留、空答案禁用与一次提交。
- 录音启停、实时转写、转写编辑、TTS 控制与语音降级。
- 断线重连、重复结束事件、主动关闭确认与资源清理。
- creating、grading、failed、ready 及结果比较。
- 正式 `InterviewClient` 的现有行为回归。

自动化门禁至少执行 frontend lint、typecheck、test、build 和 `git diff --check`。由于共享运行层会影响正式面试，还要运行其现有实时与语音测试。

真实验收启动依赖与三端服务，验证报告入口 → 弹窗创建 → 单题文字回答 → 一次结束 → 批改 → 对比结果，并验证数据库中的练习隔离。浏览器同时检查桌面与移动布局。真实 WebSocket 语音降级可验证本地 provider 未配置边界；外部云 ASR/TTS 质量只有在真实密钥可用时才算验收。
