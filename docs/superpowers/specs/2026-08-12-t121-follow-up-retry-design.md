# T-121 主问题与追问重练设计

## 目标

把报告页的重练目标从“整道主问题”扩展为“主问题或任意一条追问”。重练主问题时允许 Mira 按正式面试规则动态追问，最多三层，随后直接结束练习并批改；重练某条追问时只回答该追问一次，不再产生后续追问。

## 产品行为

- 主问题卡底部提供“重练主问题”入口。
- 每条追问卡右上角提供“重练此追问”入口。
- 两种入口都在当前报告页打开现有独立专注答题弹窗，不跳转到正式面试页面。
- 主问题练习会显示当前主问题；每次作答后，AI 可以追问、提示、澄清或结束。追问深度沿用正式面试上限三层，但不会进入下一道大题。
- 追问练习只显示选中的历史追问；提交后直接结束并批改。
- 主问题结果比较主问题总分、回答、建议，并展示本次产生的追问链。
- 追问结果比较该条追问上次与本次的独立 0–10 分、回答、参考答案和建议。
- 作答阶段继续隐藏旧答案、旧分数和旧建议。

## API 契约

继续使用：

`POST /api/v1/interviews/{sessionId}/questions/{questionId}/retry`

请求体：

```json
{
  "targetType": "MAIN_QUESTION",
  "followUpIndex": null
}
```

- `targetType` 为 `MAIN_QUESTION` 或 `FOLLOW_UP`。
- `FOLLOW_UP` 必须携带从 0 开始的 `followUpIndex`。
- 缺少请求体时按 `MAIN_QUESTION` 处理，保持旧客户端兼容。
- Spring 必须校验报告归属、主问题归属、追问序号和追问 JSON 结构；不能接受客户端直接传入追问文本或原答案。

创建响应继续返回 `practiceSessionId` 与 `runtimeToken`。练习结果响应新增目标类型、追问序号，并允许两次尝试携带各自的追问链。

## 数据模型

`practice_session` 继续以练习会话 ID 为主键，并关联来源面试、来源主问题。新增：

- `target_type`：`MAIN_QUESTION` 或 `FOLLOW_UP`。
- `source_follow_up_index`：追问序号；主问题练习为空。
- 来源快照：目标问题文本、原回答、原评分、参考答案和建议。

快照保证历史报告即使以后重新生成或追问顺序变化，练习结果仍比较创建练习时选中的对象。已有练习记录按主问题模式兼容读取。

正式报告的 `follow_up_chain_json` 项新增可选 `score` 字段。新报告必须输出该字段；旧报告缺失时仍可读取。

练习批改结果为当前题评价增加可选 `baselineScore`。它只用于旧追问没有独立分数时：AI 在同一批改请求、同一评分标准中同时评估旧回答与本次回答；该基准分保存在练习报告中，不回写来源报告。

## AI 运行时

`InterviewStartRequest` 在 `mode=practice` 时新增 `practiceTarget`：

- `main_question`：运行正式面试的回答决策图；遇到 `follow_up`、`hint`、`redirect` 或 `clarify` 时继续对话；遇到 `next_question` 或达到三层上限时以 `practice_completed` 结束。
- `follow_up`：记录第一份候选人回答后立即以 `practice_completed` 结束，不运行决策图。

两者都只接收一个运行时问题，不生成新的大题。消息持久化、SSE、WebSocket、ASR、TTS、幂等提交、断线恢复和批改触发继续复用现有实现。

## 批改

- 正式报告批改为每条追问生成 `score`、参考答案和建议。
- 主问题练习沿用主问题评价；本次动态追问作为当前评价的追问链返回。
- 追问练习把选中的追问克隆成当前练习的唯一问题，当前得分使用普通单题得分。
- 若来源追问已有 `score`，结果直接使用快照分数。
- 若来源追问没有 `score`，Spring 在练习批改请求中附加来源回答，AI 返回 `baselineScore`，保证旧回答和新回答使用同一轮评分标准。

## 前端组件

- `ReportClient` 构造显式 `PracticeTarget`，主问题和每条追问分别触发创建请求。
- `PracticeDialog` 与 `PracticeAnswerCard` 接收统一目标对象，用目标文本作为弹窗题目；主问题作答时不显示“不追问”，追问作答时显示“不再追问”。
- 主问题运行时收到追问后继续保持答题弹窗，并将最新面试官问题作为当前提示。
- 结果面板根据目标类型展示“主问题练习”或“追问 N 练习”，追问模式展示独立分差；主问题模式额外展示本次追问链。
- 公开分享页不提供任何重练入口。

## 错误处理

- 非本人报告、错误主问题、越界追问序号或畸形追问数据返回现有 `NOT_FOUND`/`FORBIDDEN` 业务错误。
- 创建失败保留当前重试面板，不打开空运行时。
- 旧追问基准评分缺失或失败时，整次批改标记失败，不用所属主问题分数冒充追问分数。
- 运行时网络或语音供应商失败继续沿用重连与文字回退；这不代表外部云 ASR/TTS 质量验收。
- 退出未完成练习继续调用运行时结束接口，避免会话悬挂。

## 测试与验收

- Spring 集成测试覆盖主问题/追问创建、目标快照、越界与越权、兼容空请求、统计隔离以及结果组装。
- FastAPI 测试覆盖主问题最多三层追问后结束、主问题主动结束、追问一次回答后结束、幂等提交和旧追问双答案评分。
- 前端测试覆盖两个入口、请求参数、弹窗文案、主问题连续追问、追问一次结束及两种结果布局。
- 完整门禁：前端 lint/typecheck/test/build，Spring `clean check`，AI pytest/Ruff/Black，`git diff --check`。
- 真实全栈验收至少走通一次主问题重练（产生追问后结束）和一次追问重练（无后续追问），并核对数据库中来源面试不变、两个练习会话彼此隔离。

## 非目标

- 不把追问拆成新的正式 `question` 实体，也不重构整个报告数据模型。
- 不进入下一道大题，不把练习计入正式面试列表或统计。
- 不修改公开分享页的只读行为。
- 不提交、推送、合并或创建 Pull Request。
